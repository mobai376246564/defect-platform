## 4. 发现的问题（未建单）

1. **疑似缺陷：BOX 连接断开后设置下发失败，App 无提示。** Console 里有 `[BoxService] 心跳探活失败，判定连接已死` → `disconnected reason=watchdog_ping_failed`，随后两次 `Publish failed device/BUD-3E00B02E/command/set: [ObjectDisposedException]`，时间上对应 WEA-02 切换「显示时间」。App 页面开关照常切换、顶部仍显示「在线」，没有任何失败提示。需要开发确认是否复现。**这条只靠看界面发现不了，是读日志发现的。**
2. **需求与实现不一致：闹钟「响铃方式」。** 需求（三、5.1，11-03）：标题「响铃方式」，选项 伙伴叫醒 / 轻柔唤醒 / 元气起床，11:00–16:59 默认轻柔唤醒。实际：标题「叫醒方式」，选项 伙伴叫醒 / 铃声叫醒 + 7 段铃声列表，16:49 打开默认铃声叫醒。可能是需求后改、文档没更新，需产品确认以哪个为准。
3. 需求与实现不一致：提醒「伙伴来电」铃声 7 个（多了晨光、跳跳）+「从视频添加铃声」，需求是泡泡 / 暖阳 / 鼓点 / 风铃 / 欢快 5 个。
   - **补充（真机 POC 后）**：11-05 打的真机包里这两处都和需求一致，是分支上之后的代码改成了现在这样。需开发确认是故意改的还是改坏了，见 [POC 结果（真机部分）.md](POC%20结果（真机部分）.md) 第 3 节。
4. 文案差异：相册无照片提示「先添加几张照片吧」 vs 需求「先添加照片」。
5. 主观项：天气回复偏念数据。

## 5. 对正式方案的结论

- **工程零改动**：MCP for Unity 已在工程里，靠 `execute_code` 就能点按钮、读开关、输文字、截图、读 Console。项目里的自定义组件（`Switch`、`TomoInputField`）需要小适配，已写成通用脚本，放在 [unity-driver/](unity-driver/)，执行器直接复用。
- **结果要多一种「存疑」**：10 条里 3 条（文案差异、主观表述、需求与实现不一致）不能简单判失败。建议只有「明确失败」和「日志报错」才走自动建单，「存疑」留给测试确认后再建，避免把需求没更新的问题直接派给开发。
- **日志很有价值**：问题 1 是唯一的疑似真缺陷，就是从 Console 读出来的。执行器每条用例都要截取执行时段的 Console 错误并一起判断。
- **编辑器测不了的**：系统返回键 / 右滑、滚轮选择器拖动、系统相册、真实 BOX 表现、定时任务。这些要么真机测，要么标人工。
- **速度**：平均约 1 分钟一条，主要花在每一步的请求往返和等 AI 回复上。
- **额度**：这次是在当前会话里执行，没法单独计量；要在执行器用命令行版 Claude Code 跑时再测。
