## 3. 真机与编辑器的差异（重要）

真机包（BudBox 1.0.1，11-05 打包）和编辑器里的当前代码（`cn_1.0.2_mobai`）界面不一样：

| 位置 | 真机包 | 编辑器（当前分支代码） | 需求 |
| --- | --- | --- | --- |
| 闹钟编辑页 | 「闹钟铃声」：伙伴叫醒 / 轻柔唤醒 / 元气起床 + 起床播报开关；17:06 默认伙伴叫醒 | 「叫醒方式」：伙伴叫醒 / 铃声叫醒 + 7 段铃声 | 「响铃方式」：伙伴叫醒 / 轻柔唤醒 / 元气起床 |
| 提醒来电铃声 | 5 个 | 7 个 + 从视频添加 | 5 个 |
| 提醒编辑页 | 时间滚轮在页面上，无备注栏 | 时间收成一行，有 0/50 备注栏（需求 11-05 新增） | — |

说明分支上 11-05 之后又改了闹钟 / 提醒页面。所以 POC 编辑器报告里的问题 2、3 应该**由开发确认是故意改的还是改坏了**，不是需求文档过时。这也说明：**执行记录必须记下包版本 / 分支 / commit**，否则同一条用例在两个环境结果不同时说不清。

## 4. 真机方案要补的三件事

1. **中文输入**：`adb shell input text` 不支持中文。办法：测试机装一个开源的 ADB 输入法（如 ADBKeyBoard，通过广播输入任意文字），执行器输入时临时切换、结束后切回原输入法。需要测试同意在测试机上装。
2. **点偏**：纯看图在“点击后布局变化”时容易点错位置（WEA-02 实际发生）。办法：执行器规定每次点击后都重新截图确认结果再进行下一步（POC 里就是这样发现并纠正的），代价是更慢、更费额度。
3. **游戏日志**：真机包的 logcat 里没有任何游戏自身日志（只有系统警告），编辑器里发现的那类“下发失败”问题在真机上看不到。办法二选一：测试包打开 Unity 日志输出到 logcat；或执行器失败时调用 App 已接入的 `BugReportService` 收集的日志文件。

另外，如果后续真机用例量大、点偏问题多，再考虑测试包接入 AltTester 之类的 SDK，按名字找按钮。按这次的表现，**第一期可以先不接**。
